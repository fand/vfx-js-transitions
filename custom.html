Custom Transitions

A transition is a fragment of GLSL that defines vec4 transition(vec2 uv, float t). VFX-JS adds the prelude, the textures and main.

shaderTransition

Give it a name and the frag. Declare your own uniforms, set defaults, and pass values with each run. Use it anywhere a preset goes.

readFrom and readTo swap when reverse is true, so write only the forward animation.

wipe.ts
import { shaderTransition } from "@vfx-js/core";

export const wipe = shaderTransition({
  name: "wipe",
  frag: `
uniform float softness;
vec4 transition(vec2 uv, float t) {
  float m = smoothstep(t - softness, t + softness, uv.x);
  return mix(readTo(uv), readFrom(uv), m);
}
`,
  uniforms: { softness: 0.05 },
});

t.run(swap, { transition: wipe, uniforms: { softness: 0.1 } });

What the prelude gives you

readFrom(p)
The content you leave. Transparent black outside [0, 1].
readTo(p)
The content you enter.
inRange(p)
Whether p is inside [0, 1]. Guard with it when you wrap or shift uv, so a container overflow doesn't draw outside the element.
t
Progress, 0 → 1, smoothstep eased.
resolution
Element size in physical px.
time
Seconds since VFX-JS started.
reverse
1.0 when playing in reverse. You rarely need it.

Draw outside the box

By default a transition draws only inside the element. Set overflow to true for the whole canvas, or a number for CSS px on every side. Then uv goes below 0 and above 1 outside the element.

The run's options win over the def's own value. This site passes overflow: 0 on the page outlet, so zooms never cover the header.

zoom.ts
export const zoom = shaderTransition({
  name: "zoom",
  overflow: true,
  frag: `
vec4 transition(vec2 uv, float t) {
  vec2 uv1 = (uv - 0.5) * (1.0 - t) + 0.5;
  vec2 uv2 = (uv - 0.5) / (t * 0.999 + 0.001) + 0.5;
  vec4 to = inRange(uv) ? readTo(fract(uv2)) : vec4(0.0);
  return mix(readFrom(uv1), to, t);
}
`,
});

Transition effects

Some looks need more than one shader: a datamosh, a pixel sort. A def's create() can return your own effects, which see the run on their context.

create()
On the def. Makes the effects for one container when a run uses the def. Later runs with the same def reuse them; switching to another def and back calls it again.
start(run)
Once per run, while the old content is held.
update(ctx)
Every frame while the animation plays. Read ctx.progress: t is eased, x is linear.
render(ctx)
Every frame of the run. ctx.from is the old content, ctx.src the new one. Pass the input through while ctx.holding.
end()
Once when the run ends, is dropped or is cancelled.
ctx.cut()
Ends the run now and shows the new content.

State lives on the effect

Each container gets its own effects, so keep per-run state on the instance.

Transition effects follow the Effect API, so you can extend an effect from @vfx-js/effects.

pixelsort.ts
const cut = shaderTransition({
  name: "pixelsort",
  frag: `
vec4 transition(vec2 uv, float t) {
  return t < 0.5 ? readFrom(uv) : readTo(uv);
}
`,
});

class Sort extends PixelSortEffect implements TransitionEffect {
  start() {
    this.params.range[0] = 1;
  }
  update(ctx: TransitionEffectContext) {
    // Fully sorted at the halfway swap.
    this.params.range[0] = Math.abs(1 - 2 * ctx.progress.t);
  }
}

export const pixelsort: TransitionDef = {
  name: "pixelsort",
  create: () => [cut.create(), new Sort({ range: [1, 1] })],
};
