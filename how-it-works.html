How It Works

  1. Snapshot. VFX-JS captures the element's current content into a texture. The old page is held on screen.
  2. Swap. Your callback changes the DOM. A router swap, a setState, innerHTML — anything. With slides already in the DOM, show(slide) writes it for you.
  3. Capture. After images, videos and fonts load, VFX-JS captures the new content.
  4. Shade. A fragment shader mixes the two textures while t goes from 0 to 1.

The DOM stays DOM

At rest the element is your plain markup. VFX-JS wraps it only while a run is in flight, then unwraps it. Text stays selectable, links stay clickable, and screen readers see the real page.

With html-in-canvas the capture uses drawElementImage. Without it, VFX-JS falls back to dom-to-canvas, which is slower.

t is eased for you

Your shader gets t from 0 to 1 with a smoothstep ease. TransitionEffect hooks also get the linear ctx.progress.x and ctx.deltaTime in seconds.

With reverse: true, readFrom and readTo swap and t plays backward. You only write the forward animation.

Fixed size, shared box

Give the target a fixed size: a viewport-sized outlet, a tab panel with a height, a slide stage. Old and new content then share one box, and the shader only mixes pixels.

Pages can still scroll inside the box. This site does that: the outlet is fixed and each page scrolls on its own.

style.css
.outlet {
  height: 100dvh;
  overflow: hidden;
}
.page {
  height: 100%;
  overflow-y: auto;
}

Which spec wins

Each field of a run is picked in this order:

  1. The RunOpts passed to run()
  2. The options from addTransition or the component props
  3. For ease, the def's own ease, then smoothstep

A run that sets its own transition drops the container's uniforms, so they never reach the wrong shader.

In React the run's RunOpts is one whole spec: a transition() click or setNextTransition() if set, else the incoming page's <TransitionIn>. The two are not merged.

spec.ts
const t = vfx.addTransition(outlet, { transition: crossfade });

// Keep a spec in a variable and pass it to run().
const back = { transition: swipe, reverse: true };

t.run(swap, back);
t.run(swap, { duration: 2 }); // crossfade, 2 s

Limitations

Nested VFX elements freeze

VFX elements inside the container stop during a run and show their plain content.

<body> can't be the target

Target the router outlet instead, like <main>.

Size changes aren't animated

If the new content has a different size, the box stays at the old size during the run and jumps afterwards.

One pending click spec per page

All <VFXTransition>s on the page share it.

No multi-page navigation

Cross-document navigation isn't supported. With Turbo or htmx, call core run(cb) by hand.
